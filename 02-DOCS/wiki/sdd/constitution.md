# pacho-app — Constitution

> Version: v1.0.0 · Ratified: 2026-10-25 · Last amended: 2026-10-25
> The non-negotiable principles every rsc-sdd phase obeys. Architectural detail lives in
> `.agents/AGENTS.md` and `02-DOCS/wiki/`; this file ratifies the principles and links the enforcement.

## 1. Stack canon

1. **Core runtime & framework**: React 19 + TypeScript + Vite. Pinned in `package.json`.
2. **Styling & Theme**: Tailwind CSS 3.4 with CSS Variables for Dark/Light mode tokens (`index.css`). Theme toggle state persists in `localStorage`.
3. **Animations & Icons**: Framer Motion for micro-interactions; Lucide React for UI icons (custom standalone SVG for GitHub in `src/components/ui/GithubIcon.tsx`).
4. **Architecture**: Modular presentation hierarchy (`layout/`, `sections/`, `emulator/`, `ui/`, `context/`).
5. **Zero-Backend in-memory emulator**: Interactive mobile mirror runs 100% in-memory with deterministic mock data (`src/data/mock-data.json`), resetting on reload without external backend or database calls.

## 2. Quality bar

6. **Audit gate**: `npm run audit` must pass cleanly before any merge or commit (executes `npm run i18n:check`, `tsc -b`, and `vite build`). Zero build errors and zero warnings.
7. **Type discipline**: TypeScript strict mode enabled (`strict: true`). Explicit `any` is prohibited without written architectural justification.
8. **App sync discipline**: `npm run sync:app` keeps public showcase features synchronized with the companion app repository (`../pacho/02-DOCS`).

## 3. Conventions

9. **Zero hardcoding (i18n)**: Hardcoded UI strings in JSX/TSX are strictly forbidden. All user-facing text must use `t('key.subkey')` from `src/context/I18nContext.tsx` with 100% key parity between `src/locales/es.json` and `src/locales/en.json`.
10. **Pricing & Subscriptions**: Subscription models and tiers are declared in `src/types/pricing.ts` but strictly decoupled and hidden from public landing views until official mobile launch.
11. **Naming**: PascalCase for React components (`InteractivePhoneEmulator.tsx`); camelCase for hooks and utilities.

## 4. Branching & shipping

12. **Git authorship is the human's**: Commits and PRs are strictly authored by the human owner. No `Co-Authored-By` an AI, no automated AI attribution footers.
13. **Commit convention**: Conventional Commits format (`feat:`, `fix:`, `refactor:`, `docs:`, `chore:`).
14. **Human confirmation gate**: Explicit human approval is required before committing or pushing changes.

## 5. Security & privacy floor

15. **No secrets or private credentials**: No private API keys or database connection strings are committed. The showcase is purely client-side static web.
16. **Data privacy**: Fictitious mock transactions and user profiles only. No personal identifiable information (PII) or user telemetry stored.

## 6. UX & accessibility floor

17. **Accessibility floor**: Follow WCAG AA guidelines with keyboard navigability, clear contrast in both light and dark themes, and descriptive `aria-label` tags on icon-only interactive controls.
18. **Mobile-first responsiveness**: Fluid layout adapts seamlessly from small mobile screens (320px) to ultra-wide displays.

## 7. Knowledge & decisions

19. Significant architectural and design decisions are logged in `02-DOCS/wiki/harness/decisions.md` and synced with Engram memory (`.engram/`).

## Definition of Done (the merge bar `verify` runs against)

A change is complete and ready to ship only when ALL hold:

- [ ] `npm run audit` passes clean (i18n key parity, TypeScript checks, Vite production build) (principles 6, 9).
- [ ] No `any` or strict TypeScript violations (principle 7).
- [ ] Zero hardcoded UI strings; translations added to both `es.json` and `en.json` (principle 9).
- [ ] Theme toggles cleanly between light and dark modes with proper contrast (principles 2, 17).
- [ ] Emulator operations maintain zero-backend isolation and state resets on reload (principle 5).
- [ ] Pricing models remain decoupled and hidden from public views (principle 10).
- [ ] Human confirmation obtained before git actions (principle 14).
- [ ] Conventional Commit format with human authorship only (principles 12, 13).
